PHASE 1 - UNDERSTAND THE END RESULT
===================================

The finished system must perform this complete flow:

1. ESP32 or simulator publishes distance telemetry.
2. AWS IoT Core receives the MQTT message.
3. An IoT Topic Rule invokes the ingestion Lambda.
4. The ingestion Lambda validates the reading.
5. DynamoDB stores the current slot state and historical events.
6. API Gateway HTTP API invokes the dashboard API Lambda.
7. The S3 static website dashboard reads data from API Gateway.
8. The dashboard API creates daily CSV reports in the private reports bucket.
9. CloudWatch stores Lambda logs.
10. Terraform and the cleanup script can destroy the deployed resources.

The project is not complete if the dashboard only runs locally.

PHASE 3 - PREPARE AWS ACADEMY
=============================

3.1 Start the lab
-----------------

1. Sign in to AWS Academy.
2. Open the Learner Lab.
3. Start the lab.
4. Wait until the AWS indicator shows that the lab is ready.
5. Open AWS Details or the equivalent credentials panel.
6. Display the AWS CLI credentials.

AWS Academy credentials are temporary. They normally contain:

- aws_access_key_id
- aws_secret_access_key
- aws_session_token

The session token is required. Credentials expire when the lab session expires
or is reset.


3.2 Configure temporary AWS credentials on Windows
--------------------------------------------------

In PowerShell:

  New-Item -ItemType Directory -Force "$HOME\.aws"
  notepad "$HOME\.aws\credentials"

Paste the complete AWS Academy credentials block exactly as provided. It should
look similar to this:

  [default]
  aws_access_key_id=TEMPORARY_VALUE
  aws_secret_access_key=TEMPORARY_VALUE
  aws_session_token=TEMPORARY_VALUE

Do not put these credentials in the project repository.
Do not put them in fyp.md.
Do not commit them to Git.

Set the region and output format:

  aws configure set region us-east-1
  aws configure set output json


3.3 Verify AWS identity and region
----------------------------------

Run:

  aws sts get-caller-identity
  aws configure get region
  aws iot describe-endpoint --endpoint-type iot:Data-ATS

Required results:

- get-caller-identity returns the AWS Academy account and ARN.
- region returns us-east-1, or the region selected for the project.
- describe-endpoint returns an AWS IoT data endpoint.

If get-caller-identity reports ExpiredToken, refresh the credentials from the
currently running Learner Lab.


3.4 Find the AWS Academy Lambda execution role
-----------------------------------------------

Run:

  aws iam get-role --role-name LabRole --query "Role.Arn" --output text

If that fails or returns no role, run:

  aws iam get-role --role-name VocLabs --query "Role.Arn" --output text

Save the returned role ARN. It should resemble:

  arn:aws:iam::123456789012:role/LabRole

If both commands return AccessDenied, inspect the AWS Academy console for the
existing LabRole or VocLabs role ARN. Do not create a new administrator role.


3.5 Understand the AWS Academy permission risk
-----------------------------------------------

The project requires permission to create or configure:

- Lambda functions using LabRole or VocLabs
- iam:PassRole for that existing role
- DynamoDB tables
- S3 buckets and static website configuration
- Public-read object policy for the dashboard bucket only
- S3 public-access-block settings for the dashboard bucket
- API Gateway HTTP API
- AWS IoT Topic Rule
- Lambda invoke permissions
- CloudWatch log groups

AWS Academy may block one or more of these operations. The generated deployment
must fail clearly when a required permission is blocked. Do not silently replace
the official S3 dashboard with local hosting.

PHASE 8 - TEST THE DEPLOYED API
===============================

8.1 Health endpoint
-------------------

Run:

  curl -sS "$API_URL/health"

Expected result:

- HTTP success response.
- JSON indicating that the API is healthy.


8.2 Test direct fallback ingestion
----------------------------------

This verifies the shared ingestion behavior even if AWS IoT Rule creation is
blocked.

Publish an available reading:

  curl -sS -X POST "$API_URL/ingest-test" \
    -H "Content-Type: application/json" \
    -d '{"slotId":"A01","distanceCm":80,"deviceId":"api-test-A01"}'

Publish an occupied reading:

  curl -sS -X POST "$API_URL/ingest-test" \
    -H "Content-Type: application/json" \
    -d '{"slotId":"A01","distanceCm":14.2,"deviceId":"api-test-A01"}'

Publish a sensor error:

  curl -sS -X POST "$API_URL/ingest-test" \
    -H "Content-Type: application/json" \
    -d '{"slotId":"A02","distanceCm":999,"deviceId":"api-test-A02"}'

Expected results:

- A01 changes from AVAILABLE to OCCUPIED.
- A02 becomes SENSOR_ERROR.
- Responses contain useful JSON rather than internal stack traces.


8.3 Test slot endpoints
-----------------------

Run:

  curl -sS "$API_URL/slots"
  curl -sS "$API_URL/slots/A01"
  curl -sS "$API_URL/events?slotId=A01&limit=20"

Expected results:

- /slots contains the summary and slot records.
- /slots/A01 returns A01.
- /events returns the first-reading and status-change events.


8.4 Test input validation
-------------------------

Run:

  curl -i -X POST "$API_URL/ingest-test" \
    -H "Content-Type: application/json" \
    -d '{"slotId":"bad slot id!","distanceCm":20}'

  curl -i "$API_URL/events?slotId=A01&limit=999"

Expected result:

- Both invalid requests return HTTP 400 with clear messages.


8.5 Test maintenance behavior
-----------------------------

Set maintenance:

  curl -sS -X POST "$API_URL/admin/slot/A01/maintenance"

Send normal telemetry while maintenance is active:

  curl -sS -X POST "$API_URL/ingest-test" \
    -H "Content-Type: application/json" \
    -d '{"slotId":"A01","distanceCm":80,"deviceId":"api-test-A01"}'

Read the slot:

  curl -sS "$API_URL/slots/A01"

Expected result:

- A01 remains MAINTENANCE even after the normal sensor reading.
- Latest sensor values and last-seen time can still update.

Clear maintenance:

  curl -sS -X POST "$API_URL/admin/slot/A01/available"
  curl -sS "$API_URL/slots/A01"

Expected result:

- A01 becomes AVAILABLE.
- ADMIN_OVERRIDE events exist.


8.6 Test stale/offline behavior
-------------------------------

Publish a current reading to A03:

  curl -sS -X POST "$API_URL/ingest-test" \
    -H "Content-Type: application/json" \
    -d '{"slotId":"A03","distanceCm":80,"deviceId":"api-test-A03"}'

Wait at least 65 seconds without publishing to A03:

  sleep 65
  curl -sS "$API_URL/slots/A03"

Expected result:

- sensorHealth is OFFLINE.
- isStale is true.
- Effective displayed status is OFFLINE.
- DynamoDB still retains the last actual sensor status.

PHASE 16 - TROUBLESHOOTING
==========================

Problem: aws command is not found
---------------------------------

- Close and reopen the terminal.
- Confirm AWS CLI v2 is installed.
- Run aws --version from PowerShell.


Problem: terraform command is not found
---------------------------------------

- Close and reopen the terminal.
- Confirm Terraform is installed and on PATH.
- Run terraform version from PowerShell.


Problem: Python has no pip
--------------------------

- Install a normal Python distribution from python.org or winget.
- Ensure "Add Python to PATH" is enabled.
- Open a new terminal.
- Run python -m pip --version.


Problem: ExpiredToken or invalid AWS credentials
------------------------------------------------

- Start or resume the AWS Academy lab.
- Copy a fresh credentials block.
- Replace the complete [default] profile in ~/.aws/credentials.
- Run aws sts get-caller-identity again.


Problem: IAM get-role is denied
-------------------------------

- Use the AWS Console to locate LabRole or VocLabs.
- Copy its ARN manually.
- Pass the ARN to Terraform or the deployment script.
- Do not create a new administrator role.


Problem: iam:PassRole is denied
-------------------------------

- Confirm the selected ARN is exactly the provided LabRole or VocLabs role.
- Confirm the Lambda resources use that ARN.
- Record the exact AWS Academy permission error.
- Do not substitute a custom administrator role.


Problem: S3 public website or bucket policy is denied
-----------------------------------------------------

- Confirm only the dashboard bucket is configured for public object reads.
- Confirm the reports bucket remains private.
- Record the exact AccessDenied error.
- Do not silently claim that local hosting completes the official deployment.
- Explain that AWS Academy blocked the required S3 website configuration.


Problem: IoT Topic Rule creation is denied
------------------------------------------

- Follow the generated manual console instructions.
- Continue functional testing using POST /ingest-test.
- Continue IoT Data Publish testing only if permitted.
- Clearly state which part was blocked by AWS Academy.


Problem: AWS CLI IoT publish fails
----------------------------------

- Verify credentials and region.
- Run:

  aws iot describe-endpoint --endpoint-type iot:Data-ATS

- Confirm the script passes the returned endpoint using --endpoint-url.
- Confirm the topic is smart-parking/slot/SLOT_ID/telemetry.


Problem: Lambda reports import errors
-------------------------------------

- Inspect the Lambda zip files.
- Ensure app.py and both shared modules are importable.
- Re-run scripts/package_lambdas.sh.
- Re-deploy the Lambda packages.


Problem: DynamoDB rejects float values
--------------------------------------

- Confirm all decimal-capable values use Decimal(str(value)).
- Confirm nested rawPayload numbers are converted recursively.
- Confirm API responses convert Decimal back to JSON-safe numbers.
