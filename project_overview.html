Smart Parking IoT Prototype

A Meaningful Cloud Solution Architected for Security, Reliability, and Infinite Scale

☁️ Achieving a Meaningful Cloud Solution

Many IoT university projects rely on local servers, direct database connections from microcontrollers, or simple monolithic scripts. This project was built to transcend those limitations by demonstrating a meaningful, enterprise-grade cloud architecture.

What makes this solution "meaningful" is its 100% Serverless and Event-Driven nature. In the physical world, parking events are sporadic—a car arrives, stays for hours, and then leaves. Traditional servers would sit idle for hours, wasting electricity and compute budget. By adopting a serverless cloud architecture (AWS Lambda, API Gateway, DynamoDB), this system fundamentally aligns computing costs with real-world physical events. It scales instantly from zero to thousands of concurrent vehicles processing telemetry, and scales right back to zero, ensuring cost-efficiency and zero server maintenance.

Furthermore, the entire cloud infrastructure is defined through Infrastructure as Code (Terraform), proving that the architecture is not a manual, fragile click-through setup, but a robust, version-controlled, and reproducible engineering solution.

🔒 Pillar 1: Security (Defense-in-Depth)

In the context of the AWS Well-Architected Framework, the Security pillar focuses on protecting information, systems, and assets. IoT systems are notoriously vulnerable to physical tampering and data injection. This project implements a multi-layered "Defense-in-Depth" strategy:

  • Encryption in Transit (mTLS): The physical ESP32 sensors do not use simple passwords. They authenticate to the cloud using Mutual TLS (mTLS) with X.509 device certificates. This means the cloud mathematically verifies the physical identity of the sensor, and the sensor verifies it is talking to the real AWS cloud, preventing Man-in-the-Middle (MitM) attacks.
  • Multi-Layer Input Validation: Data from the physical world is inherently untrustworthy. Telemetry payloads pass through an IoT SQL topic filter, then undergo strict regex validation, numeric bounds checking (enforcing physical ultrasonic limits), and status whitelisting before ever touching the database.
  • Cross-Site Scripting (XSS) Prevention: All data fetched from the cloud is aggressively sanitized using HTML entity encoding before being injected into the web dashboard, ensuring that even if malicious data somehow bypassed the backend, it cannot execute in the user's browser.

🔄 Pillar 2: Reliability (Self-Healing)

The Reliability pillar focuses on a system's ability to recover from failures, mitigate disruptions, and meet operational demand. Physical hardware fails, wires get cut, and networks drop. This cloud solution is engineered to expect and gracefully handle these failures.

  • Stale Sensor Detection (Offline Resilience): The cloud backend does not blindly trust the last known state. Every time the dashboard is loaded, the backend dynamically calculates the time since the last telemetry ping. If a sensor goes silent for more than 60 seconds, the cloud proactively overwrites the frontend display to OFFLINE, preventing drivers from being routed to a "phantom" available bay.
  • Atomic Transactions: Updating a parking bay's status and logging that event into the historical ledger must happen simultaneously. The system uses DynamoDB TransactWriteItems to ensure that these two distinct database writes succeed or fail together, preventing corrupted or desynced states.
  • Graceful Degradation & Error Isolation: The architecture prevents cascading failures. If the backend fails to write an event, it catches the error and retries. If a single endpoint fails, it returns a safe HTTP 500 without leaking stack traces. The ESP32 firmware utilizes hardware timeouts to prevent infinite blocking loops and auto-reconnects seamlessly if Wi-Fi or MQTT drops.

⚙️ How the AWS Services Execute this Vision

Every AWS service in this architecture was intentionally selected to fulfill the goals of Security, Reliability, and Serverless scalability.

📡 ESP32 & HC-SR04 (Edge)

The Physical Interface: Collects raw distance data using ultrasonic waves. Responsible for initiating the secure mTLS handshake and executing self-healing loops to maintain a persistent connection to the cloud, regardless of local network instability.

☁️ AWS IoT Core

The Secure Gateway: Handles millions of concurrent device connections. It enforces the Security pillar by managing the X.509 certificate lifecycle and restricting devices to specific MQTT topics using IAM IoT Policies.

⚡ Lambda (Ingestion)

The Validation Engine: Triggered instantly by IoT Core. It serves as the primary enforcement point for Reliability (atomic database writes) and Security (scrubbing and dropping malformed physical telemetry payloads).

🗄️ Amazon DynamoDB

The Serverless Datastore: Stores real-time state and historical events. Chosen for its single-digit millisecond latency and PAY_PER_REQUEST billing, eliminating the need to provision traditional SQL servers. It provides the foundation for our transactional reliability.

🚪 Amazon API Gateway

The RESTful Router: Acts as the secure "front door" for web clients. It handles Cross-Origin Resource Sharing (CORS) preflight requests and routes traffic seamlessly to backend logic, absorbing sudden spikes in web traffic effortlessly.

⚡ Lambda (Dashboard API)

The Business Logic: Translates raw database rows into intelligent JSON responses. It executes the core Reliability feature of "Stale Sensor Detection" on-the-fly, ensuring the public web dashboard only receives highly confident, sanitized data.

🪣 Amazon S3

The Static Host: Serves the compiled HTML, CSS, and JS frontend globally. Because the frontend contains no server-side logic, hosting it on S3 guarantees 99.999999999% durability and removes the attack vectors associated with traditional web servers (like Apache or Nginx).

🏗️ HashiCorp Terraform

The Foundation: Infrastructure as Code. It ensures the Reliability of the deployment process itself. By codifying every Lambda, Bucket, and Policy, the system is immune to human configuration errors and serves as living, executable documentation of the cloud architecture.
